How On-Chain Verification Works
Every price is cryptographically verifiable on-chain. No trust required — anyone can prove the data hasn't been tampered with.
01

What is a Merkle Tree?

A Merkle tree lets you verify 276,000+ prices by storing a single 32-byte hash on-chain. Each price is hashed into a "leaf," then pairs are hashed recursively until one root remains. 

                    ┌──────────────┐
                    │  Merkle Root │  ← stored on-chain
                    │  0xfdaf...   │
                    └──────┬───────┘
                           │
                ┌──────────┴──────────┐
                │                     │
          ┌─────┴─────┐         ┌─────┴─────┐
          │  Hash AB  │         │  Hash CD  │
          └─────┬─────┘         └─────┬─────┘
                │                     │
          ┌─────┴─────┐         ┌─────┴─────┐
          │           │         │           │
     ┌────┴────┐ ┌────┴────┐ ┌────┴────┐ ┌────┴────┐
     │ Leaf A  │ │ Leaf B  │ │ Leaf C  │ │ Leaf D  │
     │Charizard│ │Pikachu  │ │Celebi   │ │Mox Ruby │
     │$1,150   │ │$3,200   │ │$355     │ │$4,453   │
     └─────────┘ └─────────┘ └─────────┘ └─────────┘
02

Double Hashing (Why It Matters)

The oracle uses double keccak256 hashing — each leaf is hashed twice. This prevents second preimage attacks where an attacker could forge a leaf from an intermediate node.

Leaf Construction
leaf = keccak256(abi.encodePacked(product_id, price, timestamp)) // OpenZeppelin hashes again internally: node = keccak256(abi.encodePacked(leaf))

Same pattern as OpenZeppelin's MerkleProof.verify() — the industry standard.
